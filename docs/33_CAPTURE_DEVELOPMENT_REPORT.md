## 今回の結論

次の優先順位は「同じ写真への適合を強める」ことではなく、寸法の根拠と独立した秤量試料を用意すること。A4の印刷マーカーを使う試作品と、開発・検証画面のデータ登録機能を追加した。マーカーは写真の平面スケールを得るための研究用機能であり、見えない麺の量や重量を認識する機能ではない。

画像縮小の安定化は再現できた一方、同じ名目100gの3写真でもパスタの画像占有率は0.178〜0.623（約3.51倍）。60gも0.135〜0.486、80gも0.156〜0.542と大きく重なる。距離・配置・束幅・重なりの影響を重量から分離できていない。100gの投影密度は0.942〜0.970とほぼ飽和し、上に重ねて隠れた麺の量を表す指標にはならない。

背景色に似た麺以外の物体、黄味の反射、画像端で切れた麺も課題。現在の自動マスクに人の正解マスクは付いていないため、抽出精度のIoUや背景除去の成功率を報告していない。画像のSHAが異なっても、物理試料が独立とは限らない。

## 研究用データ登録

通常のホーム・食事日記とは別に、「設定 → 開発・検証ツール → 独立試料・撮影データ登録」を追加した。写真と実測重量、製品名、物理試料ID、撮影日時・セッション、角度、基準物、再利用/追加関係を保存する。同じ試料の次の写真では製品・重量・試料IDを引き継げる。

自動ラベルとは利用者が入力した実測値を台帳へ記録することで、画像から正解重量を生成することではない。原本はバイト列を保持し、EXIF等を除いたプレビューは別ファイル・別SHA-256で管理する。撮影QCとマーカー検査は参考診断として扱う。

同一原本の重複登録、同じ送信の再実行、同じ試料IDへの矛盾した重量・製品・関係を検査する。既存写真との一致時は統合・上書きしない。矛盾した再送の変更前/試行値は監査記録に残す。登録データは常に学習未承認・独立性未審査。別試料を申告しても、それだけでtrain/testへ自動分割しない。

保存先は既定で `pasta_weight_app_v2/data/research_collection/`。`PASTA_RESEARCH_DATA_DIR` で変更できる。`PASTA_DATA_DIR` を別環境へ変更した場合は、その配下を既定とする。既存の `measurements.sqlite3` や学習用DBは開かない。研究専用 `collection.sqlite3` にsamples、entries、audit_eventsを持ち、原本/プレビューは別ディレクトリへ保存する。

## 撮影・独立評価計画

[改訂撮影計画](32_CAPTURE_COLLECTION_PLAN.md) を用いる。初期案は5重量×非共有6試料＝30独立試料、各3配置で90原本。重量ごとtrain3・validation1・封印test2とし、15/5/10試料に分ける。旧25試料案よりテスト試料を各重量1つ増やしたが、依然として精度保証に十分な規模とは言えない。

同じ麺を量り直すだけでは独立試料にならない。積み増し・取り分け・混合・連写・再圧縮・マスク修正は系列を継承する。撮影セッションと背景・照明が重量ラベルの代理にならないように条件をそろえ、封印テストは別の未使用試料・セッションで用意する。

独立MAE10g以内を中間目標、5g以内を最終目標とし、最大誤差・重量別誤差・拒否率・出力率も事前に固定して評価する。基準を満たすまで本番標準モデルへ変更しない。今回の一般向け推定処理は変更していない。研究画面では手動実測で登録でき、食事日記は栄養未計算でも保存できるが、一般の測定失敗画面から実測重量だけで栄養・履歴保存する完全な代替導線は今後の実装事項。入力実測値を推定値へ偽装して保存しない。

## 実行・保護・復旧

Windowsでは従来どおり、アプリフォルダで `python -m streamlit run app.py`。通常のrequirementsに加えた本番依存はない。印刷PDF再生成だけは任意のreportlabが必要。マーカー検出はOpenCVのaruco機能を使う。実験環境のOpenCV/NumPy版は結果JSONへ保存する。

研究実験の再実行例（リポジトリルート、新しい出力先を使う）：

```bash
.venv/bin/python -m pasta_weight_app_v2.experiments.capture_readiness --source pasta_weight_app_v2/data/direct_stability_v1 --output pasta_weight_app_v2/data/capture_readiness_new
.venv/bin/python -m pytest -q pasta_weight_app_v2/tests
```

研究DBはスキーマを作成/変更する前にSQLiteバックアップを保存する。未知のスキーマはバックアップ後に拒否し、勝手に移行しない。復旧時はStreamlitを停止し、現在の研究フォルダを別名で丸ごと保管したうえで、対応するバックアップDBと原本・プレビューを別フォルダへ復元し、`PASTA_RESEARCH_DATA_DIR` をそのフォルダに向けて確認する。DBのみの復元では写真ファイルは復元しない。元フォルダへ上書きせず、台帳のSHAを照合する。

今回の開始前に既存data全6,209ファイルをSHA-256記録し、約1.04GBの非公開tarへ退避した。本番推定、既存SQLite、食事日記、既存モデルを変更せず、UI変更は開発ツールの入口に限定した。実写真・ラベル・DB・非公開診断をGitHubへ公開していない。

自動テスト、ブラウザ確認、終了時保護確認の確定結果は、非公開成果物の `verification.json` と `REPORT_JA.md` に記録する。スマホ実機・Windows実機・プリンタ実機・新規独立試料での重量精度は今回未検証。
