# 撮影状態の区分

`spread` は広げた麺、`bundle_end` は束の断面を正面から撮った写真、`bundle_side` は束の側面・上面を撮った写真である。表示名はそれぞれ「広げた状態」「束の断面」「束の側面・上面（回帰用）」。既存のCLI・CSVの `bundle` は従来どおり `bundle_end` の別名として扱う。

側面・上面を丸い断面とみなしてHough円検出を適用しない。OpenCV比較評価では `bundle_side` を適用外の失敗として総数に含め、重量を捏造しない。回帰では撮影状態×製品を分けて学習し、対応するモデルがない場合は棄却する。側面写真の実物精度は未検証であり、重なって見えない麺を復元できる保証はない。

受領資料の `parallel_bundle` や `spread_and_fanned` は説明用の仮情報であり、上記モードに自動変換しない。画像と撮影方向を検品してから割り当てる。重量や計量グループの確認とは別の確認である。

## 既存DBの互換性

旧 `training_samples.mode` のCHECKは2種類しか許可しないため、初回に既知の制約だけを3種類へ拡張する。同一トランザクション内でテーブル定義を再作成し、全ID・通常列・追加列・生成列定義・削除済み行・版履歴・親参照・明示索引・トリガー・採番の上限を保持する。参照整合性とコピー内容が一致しなければロールバックする。未知のスキーマは自動で書き換えない。

変更前のSQLite全体をDBと同じ場所の `backups/` に保存する。バックアップは写真と同様にローカル専用でGit対象外。写真ファイルや既存のモデル係数は変更しない。撮影状態を側面から断面などの偽の代用ラベルへ置き換えることはしない。
