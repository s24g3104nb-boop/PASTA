# 06 テスト・受入確認計画

## 既存の自動テスト（確認済）
2026-10-28、本パッケージの元コードで `pytest -q tests/test_core.py` を実行し **4 passed**：
- `test_sample_spread`：CGの独立した広げ麺12本を検出。
- `test_sample_bundle`：CGの端面16個を検出。
- `test_nutrition`：50g・仮デモ値の栄養計算。
- `test_db_and_history`：SQLiteの商品登録と測定結果・画像保存。

**これは実写真のAI性能テストではない。Streamlitブラウザの自動テストでもない。**

## Codexが次に追加すべきテスト
- 画像：EXIF回転、PNG透過、極小/巨大、空ファイル、非画像、グレースケール、ピンボケ、暗すぎ、背景に黄色いノイズ、0本、交差麺。
- パラメータ：`min_radius>=max_radius`、負数、画素閾値の極端な値、境界値。
- 栄養計算：0g、微量、超大重量、ゼロ栄養値、負の入力拒否、桁と丸め。
- DB：製品名の重複、編集・参照・保存、データ破損時、画像保存失敗、パスの安全性、後方互換。
- 学習・評価CSV：ファイル不存在、画像欠損、重量0/負数、重複、mode値異常、batch_id別分割、再現性、未学習時の挙動。
- UI：写真なし、CG、広げ、束、手動修正、保存、履歴表示、画面幅。Playwright等は必要になれば導入。
- デプロイ：Windows上で `python` 起動、PC/スマホのアップロード、HTTPSのカメラ、認証設定。

## 推定評価の受入
- 別の実物写真で、モード別のMAE・RMSE・MAPE・成功率を自動で出せる。
- 合成サンプルの数値と実物テストの数値が同じグラフで誤解されない。
- 特定の画像での過大な自信（誤った本数でも断定）は抑える。
- 製品名と校正値が推定記録から追跡できる。

## 性能計測
- 画像1枚のアップロード時間・前処理時間・推定時間・描画時間を分けて記録。
- 初期目標「10秒以内」を実機で検証し、未達なら条件を明記。
