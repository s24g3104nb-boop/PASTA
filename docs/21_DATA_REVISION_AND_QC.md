# 私有データの訂正・QC・学習前点検

## 原本、プレビュー、候補ラベルを分ける

私有パッケージは `pasta_weight_app_v2/data/Pasta_Lens_Private_Dataset/` に置きます。最新CSVは `docs/ALL_58_PHOTO_MANIFEST.csv`、写真は `photos/` です。従来の `Pasta_Lens_42_Photos/` とSQLiteのID・履歴・検品データは維持します。正規IDは `IMG_XXXX` とし、添付時の別名、受領SHA、原本参照SHA、EXIFの向き、実寸法を別々に記録します。

プレビューと原本のSHA不一致を原本の破損と混同しません。旧プレビューは過去の受領SHAで検証し、原本参照SHAと両方保存します。統合先の同一IDに別ハッシュがあれば上書きを停止します。MPO形式のスマホJPEGは主画像を1標本として読み、EXIFを正規化します。副画像を別写真として水増ししません。

CSVの `confirmed_by_user` と `confirmed_latest_conflicts_older_note` は重量の確認情報です。`tentative_*` は候補として保持し、教師値の `weight_g` はNULLです。重量確認は、同じ麺か・同じ計量か・同じ撮影かの確認とは別です。候補をフォルダ名、撮影順、秤の見た目から確定しません。

## 取り込みと訂正

画面の「AI学習管理」→「受領パッケージ」では新旧ZIPを受信でき、最新CSVの差分を表示できます。ZIP内のツールは実行しません。最新版の同名メタデータを別内容で上書きしないため、将来の別版はまず別フォルダに保管してください。

CLIでも同じ処理を使用します。リポジトリルートで実行します。

```bash
.venv/bin/python -m pasta_weight_app_v2.dataset_revision \
  pasta_weight_app_v2/data/Pasta_Lens_Private_Dataset \
  pasta_weight_app_v2/data/Pasta_Lens_42_Photos
```

非公開の `reports/revision_dry_run.json` に受領状態、旧→新、状態ハッシュを保存します。内容を確認後、同じコマンドへ `--apply-plan <plan_sha256>` を付けると適用します。適用前にDB、従来CSV、最新CSV、差分を `data/backups/revision_*/` へ保存します。並行更新・不足・破損・実行中の学習ジョブがあれば適用を停止します。DBトランザクション失敗時にはCSVも復元します。プロセス強制終了に備え、起動し直す前にバックアップと差分を確認してください。

変更履歴は `photo_intake_audit` に保存します。同じCSVの再適用で後からの確認を消しません。変更された教師値で登録済みの画像・派生画像は隔離し、旧実験は保存したままモデルの採用を撤回します。再確認後は同じ画素なら同じ学習IDを復旧し、マスクが変わった場合は新IDで採用します。旧モデルは再有効化できず、新しい実験が必要です。

復旧はアプリを停止し、現在の `data/` 全体を別の場所へ退避してから、対象バックアップのSQLiteと `metadata/` を元の場所へ戻します。訂正時に追加した原本ファイルは削除しません。DBとCSVを一緒に復旧し、受領検査とテストを再実行してください。

## 前処理と修正

```bash
.venv/bin/python -m pasta_weight_app_v2.prepare_photo_qc \
  pasta_weight_app_v2/data/Pasta_Lens_42_Photos
```

HSV、支持領域による背景抑制、Lab色抽出を比較します。マスクは常に未承認から始まり、元RGB画素をコピーしてPNG合成します。麺を描き直す処理はありません。ROI基準寸法が不明な場合、`--infer-reference-max-side` は明示的な仮定を記録するための研究用オプションで、正しい原寸法を保証しません。座標の回転と縮小は別処理です。外れたROIを黙って切り詰めません。

画面では加工前・加工後・マスクを比較し、境界を拡大できます。HSV/Lab/支持領域の方式変更、PNGマスク、ポリゴン、指・マウスのブラシ、Undo/Redoを使用できます。修正時は承認用チェックをリセットします。ブラシは画面の縮小率を元画素座標へ変換し、最後に秤等の除外矩形を適用します。検品者・理由・日時を監査記録に残して承認・差し戻しします。ブラシの修正履歴は画面セッション内の6段階で、保存した検品履歴とは区別します。

画像端との接触、空マスク、前景のぼけ・強い反射等をフラグ化します。これは検品の優先度であり、麺の本数、隠れた重なり、正確な長さや太さの検証ではありません。背景の小物と麺が同じ色の場合は自動処理に限界があります。人によるマスク検品前には学習へ採用しません。

## 学習と公平な比較

学習前点検では、確定重量、QC承認、計量・撮影・物理試料の対応、実製品、撮影状態を分けて数えます。前点検を通っても、訓練処理がモード・製品別の独立3群以上と複数重量、別のvalidation/testを改めて検査します。同じ物理試料への麺の追加・再計量も共通IDにします。同じ撮影・計量・物理試料・同一/近似画像を推移的に連結し、固定分割を維持します。加工画像も元画像と同じ群です。

現行候補はCPUの画像特徴量＋Ridge回帰です。OpenCVの本数×製品の校正重量と同じ評価画像で比較します。束の側面に断面検出器を適用しません。製品校正がない場合のOpenCV失敗も評価表に残します。追加のRandomForest・深層モデルは未実装です。

実験スナップショットにはデータSHA、分割、依存版、Python版、seed、alpha、特徴量版を記録します。MAE/RMSE/MAPE/中央値AE/バイアス/失敗率、重量・状態・製品別誤差、訓練にない重量、群数と推論秒数を保存します。両方式が成功した共通集合の誤差と、全画像の成功率を区別します。独立校正群がないため予測区間・カバレッジは未算出です。学習成功だけでは自動採用しません。選択したモデルも撤回してOpenCVへ戻せます。

`pasta_ml.leakage.background_diagnostic` は承認済みマスクと独立評価群に対して、前景の暗/灰背景置換、背景のみの対照を比較します。候補重量・未承認マスク・訓練群の混入を拒否します。背景のみでも予測できる場合は警告しますが、マスク形状も残るため単独で背景学習の証明にはなりません。現在の写真が条件を満たさない場合、対照の精度も算出しません。

公開対象はコード、合成画像によるテスト、秘密を含まない説明書です。私有CSV・写真・マスク・DB・モデル・レポートはコミットしません。公開対象パスの検査は秘密情報の全内容を保証する検査ではないため、ステージした差分も確認します。認証のないStreamlit管理画面を公開しません。

Windowsでは `.venv/bin/python` を `.venv\Scripts\python` に読み替えます。ブラウザのスマホ幅とブラシ通信は合成画像・localhostで確認しています。スマホ実機のカメラ、HTTPS、Windows実機、Cloudflareの過去の400は未検証です。料理名は手動選択のまま、乾麺履歴と入力した材料量を使って料理全体・1人分のkcal/PFCを計算します。写真から材料の使用量や完成料理の重量を求めません。
