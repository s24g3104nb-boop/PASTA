# 乾麺1枚撮影の検証手順

## 最初に2〜3枚でA4基準を確認する

アプリで **設定 → 開発・検証ツール → A4基準の試し撮り** を開きます。この画面からA4 PDFと20枚の撮影台帳を取得できます。検品結果は写真ごとにJSONで保存できます。試し撮り画面から測定履歴や学習データへの登録は行いません。

1. PDFをA4の普通紙に「実際のサイズ」「100%」で印刷します。自動拡大や「用紙に合わせる」を外します。下部の線の両端を定規で測ります。目安は100mmから±1mmです。印刷を変えたら再測定します。
2. 紙を平らな台に固定し、標準カメラの1倍で用紙だけを真上約55cmから撮ります。可能なら別の定規を紙面に沿って置き、100mm区間を一緒に写します。用紙全体、マーカー0〜3とその余白が入るか確認します。
3. 約200gの密集した束を置き、真上約35cmから撮ります。束全体と用紙を一度に写せる距離へ調整し、実際の値を記録します。長い束はマーカーを覆わない向きに置きます。光沢トレーがマーカーを覆う場合や反射が麺にかかる場合は、紙または反射の少ない無地の台を使い、照明を拡散します。
4. 3枚目を撮る場合は束を動かさず、約55cm・真上から15度傾けて撮ります。距離はレンズから紙面中央までです。1倍のまま、紙・麺・マーカーが収まったかを確認します。
5. 写真の原本を1枚ずつ検品画面に入れ、撮影の種別と実測した距離・角度・束の高さを入力します。緑の用紙輪郭と麺の候補輪郭を原本と見比べます。反射を拾う、麺の両端が消える、マーカーが欠ける場合は条件を直して再撮影します。

紙面への投影面積・長さ・幅を表示します。厚い束では紙面から浮いた表面の見かけ寸法が変わり、下層の麺は観測できません。実際の基準寸法は印刷物と定規で確認してください。PDFのA4寸法・100mm線、生成画像での座標補正と欠けの判定は試験済みです。実印刷・スマートフォンでの寸法誤差は試し撮りで測ります。

## 条件確認後の20枚

同じ製品を使い、120・160・200gを目標に各2試料を別々に量ります。6試料間で麺を再利用せず、それぞれを別の容器に分けます。秤の表示値、秤の分解能、製品名・太さ、試料IDを控えます。合計は名目960gです。

| 対象 | 撮影条件 | 枚数 |
|---|---|---:|
| シートだけ | 真上約35cmと真上約55cm | 2 |
| 密集した6試料 | 各試料を真上約35cm、真上約55cm、約55cmで真上から15度 | 18 |

35cmで収まらないときは、すべての重量に共通する近距離を決め直し、実測値を台帳に記録します。同一試料の3枚の間は束の並びと量を保ちます。実測距離、角度、束の高さ、カメラとレンズ、原本ファイル名、再利用の有無を記録します。秤の表示を残す場合は基準の証拠用に別撮りし、モデルへ渡す写真には入れません。1回の予測は写真1枚で行います。同一試料の3枚は撮影条件への感度の比較に使います。

この20枚は撮影手順のパイロットです。条件確認に使った麺は、最終テストの試料に再使用しません。今後の開発後に封印したテストを回す際は、重量、距離、角度、成功率・停止率を併記します。

## 来歴の追記と実験

来歴の訂正は原本、元のmanifest、重さのラベルを保ったまま、新しいJSONに記録します。撮影者が確認した順序を `--weights` に設定します。親から後段への追加関係を記録し、一つの物理系列として取り扱います。他のバッチとの材料共有関係は、人が別途確認します。未確認の写真は独立分割から除外します。

以下の実験コマンドは、GitHubから取得したリポジトリのルートで実行します。

```text
python -m pasta_weight_app_v2.experiments.lineage_revision --batch ORIGINALS --output NEW_REVISION.json --weights W1 W2 W3 --series-id SERIES_ID --confirmed-on YYYY-MM-DD --evidence "撮影者が確認した追加関係"
python -m pasta_weight_app_v2.experiments.weight_robustness --dataset ORIGINALS --dataset OTHER_ORIGINALS --lineage-revision NEW_REVISION.json --output PRIVATE_NEW_OUTPUT
python tools/check_real_photo_flow.py --research-lab --dataset ORIGINALS --dataset OTHER_ORIGINALS --output PRIVATE_NEW_REPLAY.json
```

方式Aは現行HSVとHSV＋Labを比較します。Labで枠の色が消えても、元のHSVマスクで麺候補につながっていた縁には見切れ警告を残します。撮影条件を明記した既知本数の別試料で確認した後に、標準方式を更新するか判断します。画面の再生テストは実写真と隔離DBを使い、人工の校正値で画面と重量計算の接続を確認します。

方式Bは従来の画像全体に対する比率、背景を抑えた束自体の形状比、内部質感、背景の色と明るさを比較します。特徴抽出は写真ごとに同じ経路を使います。直近の被写体写真は既知重量の原本で探索的に当てはめ、縮小・回転・JPEG・明るさ・画面内サイズ変更は同じ原本の変化として記録します。背景由来の特徴も比較することで、撮影条件と重量の交絡を確認します。出力先は既存の実験結果から分離し、モデルは本番へ登録しません。

## 検証と独立評価

`weight_evaluation`は来歴と分割の指紋を確認します。JSONに`records`、`assignments`、`material_parents`、`predictions`、`model_card`を含めます。重い範囲の評価では計画時に決めた`target_weights_g`を追記します。各写真は実測値`measured_g`と目標値`nominal_weight_g`、`distance_cm`、真上からの`tilt_deg`を分けて記録します。評価に使用した各原本には、得られた`predicted_g`、または`null`と停止理由を持たせます。任意の`transformed_predictions`で同一原本の派生画像との変動を比較できます。

```text
python -m pasta_weight_app_v2.experiments.weight_evaluation --partition validation --input PRIVATE_VALIDATION.json --output NEW_VALIDATION_REPORT.json
python -m pasta_weight_app_v2.experiments.weight_evaluation --partition test --input PRIVATE_TEST.json --output NEW_TEST_REPORT.json
```

MAE・RMSE・最大絶対誤差は重量を出せた写真で集計し、試料ごとの重みも均等にした指標を併記します。停止画像も成功率の分母に残します。独立試料MAE 5g以内を目標とし、既存の採用の目安には成功率や標本数の確認も含まれます。検証集計と独立テストの結果は別出力です。物理試料の独立性、実測ラベル、条件設定は人が確認します。
