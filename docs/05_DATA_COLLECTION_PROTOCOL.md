# 05 乾麺の写真と実測重量を集める手順

## 写真を撮れるようになったらユーザーにお願いすること
1. 乾燥スパゲッティは最初は**1製品に限定**する。パッケージから製品名・直径(mm)・標準長さ(cm)・乾麺100gあたり栄養値を転記。
2. 電子はかりで正確に重量を測る。器を使う場合は風袋引き。小さい重さは測定誤差に注意。
3. 実物と重量の対応付け用に、`batch_id` を設定する。同じ20gを繰り返し撮影した画像はすべて同じbatch_id。
4. 同じ重量を「広げ（重なり少なめ）」「束の先端（断面）」で撮影する。**写真内にマーカーは置かない**。
5. 背景・光・カメラ位置を少しずつ変え、条件をCSVに記録する。ピンぼけ・交差のような失敗例も捨てない。
6. 同じバッチの連写をtrain/test両方に分けない。
7. 写真を加工せず保存。EXIFや位置情報が含まれることがあるため共有先を管理し、必要なら撮影位置情報を除去。

## 最初の試運転（最低限）
- 20g、50g、100g を各「広げ」「束の断面」で1枚ずつ：**合計6枚**。これは解析可否を見るための**予備撮影であり、AIの学習に十分ではない**。
- 1本の重量を校正する場合は、同じ製品を数十本以上数えて複数回計量し、平均とばらつきを取る。

## 本格的な学習データ
- 量の違いだけでなく、秤量バッチ、光源、撮影距離、カメラ機種、麺の重なり具合、束の密度を変える。
- 初期目安として各モードで**数十〜数百の独立した秤量サンプル**を目指し、予備検証結果によって必要量を再見積もる。これは保証された必要枚数ではない。
- 対象重量は20〜150gなど、実際の利用範囲でバランスを取る（ほかの範囲が必要なら追加）。
- 未見のブランドへの汎化を評価したいなら、別ブランドを後で追加して「学習未使用製品」でテストする。

## CSVテンプレート
`../dataset/dataset_template.csv` を参照（ヘッダーのみ、架空サンプル値は入っていない）。

必須フィールド：
- `image_path`：データセットルートからの相対パス
- `batch_id`：1回の秤量ごとのID
- `product_id`：製品識別
- `mode`：`spread` / `bundle_end`
- `actual_weight_g`：秤量値（0より大きい実測値）
- `captured_at`：撮影日時（必要に応じて記載）

推奨：`individual_strand_count`（実測本数が判るときのみ）、`lighting`,`background`,`occlusion_level`,`device_label`,`session_id`,`notes`。見えないものの「推定本数」を真のラベルと混同しないこと。

**写真が今すぐなくても**：CodexはCSV検証・データ分割・評価・訓練入口まで実装可能。実写モデルの学習自体は実データ到着後。

## 2026-10-28 追記: ユーザー既保有の写真
- **20g・40g・60g・80g・100g** の乾麺写真がユーザーにある（数量・撮影状態・撮影条件・製品名は未確認）。
- 受領したら最初にこれらを登録し、写真ファイル名・重量・モード（束/広げ）・製品・秤量バッチ・撮影セッションを表にする。
- 同じ束・同じ秤量を角度違いで何枚撮影したとしても、学習／評価を分けて重複させない。
- この5重量帯だけでは連続的な任意重量の精度は保証できない。まず小規模データで推定可能性とエラー傾向を評価する。
