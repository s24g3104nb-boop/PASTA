# AI学習管理画面と再学習

## ローカル画面での流れ

1. リポジトリREADMEの方法で起動する。「パスタデータ」で実製品・太さ別の名前、100g栄養値、OpenCV比較用の1本gを登録する。同じ銘柄でも直径・長さが違う場合は別製品として管理する。
2. 「AI学習管理」でJPEG/PNG、電子はかりの実測g、状態、製品、秤量バッチID、撮影セッションIDを入力して登録する。種類、太さmm、ISO撮影日時、照明、背景も記録できる。重量は写真名から推測せず、未入力・非有限・0以下を拒否する。同じ重量の写真は何枚でも登録できるが、同じ画像の重複は拒否する。
3. 一覧で写真を選び、ラベルを修正したり今後の学習対象から削除できる。版番号による同時編集検知と変更履歴を残す。削除は対象外にする操作であり、実験再現のため写真と過去スナップショットは保持する。加工画像には元画像IDを指定し、重量・製品・状態・バッチ・セッションは元画像と揃える。
4. 「CPU学習を開始」を押す。別のPythonプロセスが画像の検査、スナップショット、分割、回帰学習、val評価を行う。画面にはすぐ戻り、「進行状況・モデル一覧を更新」で段階・枚数・終了・失敗理由を確認できる。同時学習は1件に制限する。止まったワーカーは次回確認時に失敗として記録する。
5. 保存されたモデルを選び、同じval写真の回帰とOpenCVを比較する。MAE/RMSE/MAPE・中央値絶対誤差・偏り・成功率・失敗数、重量別・モード別の表、実測g対推定gの散布図を表示する。OpenCVには実製品の校正値が必要で、未校正は失敗数に含める。
6. 実写モデルでval推定が1件以上成功した場合のみ測定用に選択できる。これ自体は実用精度の保証ではない。測定画面の「学習モデル」を選択し、同じ製品・モードで新しい写真を試す。モデルIDを履歴の方式に保存し、回帰では本数を数えていないため本数欄は空欄にする。

## 小さいデータと評価の制約

5種類の重量を分類する方式ではない。画像特徴量から重量gを連続回帰する。独立した35g・75g等の実測写真を別に確保し、訓練に含めず検証する必要がある。写真の実物や撮影条件が不明なまま精度は決められない。

同じbatch/session、同一画素、近似画像を推移的に同じグループへまとめる。各製品×モードのtrainには3グループ以上・2重量以上が必要で、val/testも独立して必要。写真枚数だけで学習可能とは判定しない。少数グループの交差検証を繰り返して精度が確立したように見せることを避け、今回は固定ホールドアウトと不足時の停止を採用した。今後十分な独立試料が集まればグループ交差検証を追加できる。

実写とCGを区別する。GUI学習は実写だけを使用し、CGモデルは測定用に選べない。合成入力のバックエンド試験は実装テスト専用で、実写真性能ではない。

## 写真を追加して再学習

写真を登録・編集した後、もう一度学習開始する。各ジョブは新しいディレクトリとモデルIDを作り、旧モデル・画像・ラベル・結果を上書きしない。過去のグループ分割を台帳に保存し、新しい写真が過去の評価グループに関連する場合はその分割を引き継ぐ。古い画像の削除・セッションID変更によってval/testがtrainへ移動することも防ぐ。

追加写真が過去の異なる分割を結び付ける場合や、分割を保持した結果必要なデータが足りない場合は停止する。正しいバッチ情報を確認し、独立した写真を追加する。分割台帳を都合よく削除してやり直さない。

画面の評価は開発用valのみで、testは表示・調整に使わない。最終モデルを決めたら、モデル一覧のジョブIDから `data/training/jobs/<job-id>/dataset/split.csv` と `model.json` を使って [CLI手順](14_DRY_TRAINING.md) の `evaluate --split test --final-test` を一度実行する。test開封後の再調整は新しい未使用実写testが必要であり、過去testを繰り返して最終性能と呼ばない。画面もtest開封済みマーカーがあるモデルでは注意表示する。

## ファイルと実装

- `training_data.py`: 追加テーブル `training_samples` と版履歴、正規化画素SHA-256重複防止、EXIFなしPNG保存、変更されない実験への書き出し。
- `training_manager.py`: `training_jobs` / `training_models` / `training_split_assignments`、子プロセス、状態と結果、モデルハッシュ検証、有効モデル選択。
- `training_ui.py`: データCRUD、ジョブ状態、モデル管理、比較表・散布図。
- `measurement_ui.py`: 方式共通の結果保存と回帰測定。対応外の製品・状態、特徴範囲外、重量範囲外では結果を出さない。
- `data/training/images/` と `data/training/jobs/`: ローカル専用でGit対象外。起動前の `PASTA_DATA_DIR` で保存場所を変更できる。既存DBや写真を初期化しない。

簡易画質判定では極端な暗さ・白飛び・輪郭不足・極小画像を拒否する。ただし麺の隠れ・重なり・未知背景を完全には検出できず、範囲内の予測も正確さを保証しない。回帰とOpenCVのどちらが適切かは実写で比較する。

## 未確認の項目

実写真の学習・精度比較、スマホとWindowsの実機、長時間・大量データの性能は未確認。バックエンドと画面は合成入力による自動テストを実行している。認証は未実装なので、管理画面を外部公開しない。料理画像分類器の本格学習は乾麺検証後の別工程。
