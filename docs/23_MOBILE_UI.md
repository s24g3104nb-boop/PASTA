# Pasta Lens モバイルUI（2026-10-28）

参考イメージの温かい配色、余白、カード、大きな数値、下部ナビを採用。根拠のないカロリー達成率や食品認識の演出は追加していません。推定アルゴリズム、学習データ、評価基準は変更していません。

## 画面と操作

- **ホーム**：撮影／写真選択、最近の測定、保存した料理、撮影ヒント。CGは折りたたんだ「写真なしで操作を試す」に分離。
- **撮影**：カメラまたはJPEG/PNG入力、EXIF向き補正、プレビュー、撮影状態・製品の確認、明示的な解析開始。状態の自動判定は未実装。カメラが開かない場合は写真選択へ直接移動。
- **結果**：入力写真、大きな推定g、カロリー・PFCカード、実測値入力、履歴保存、再撮影。検出パラメータ・マスク・手動本数は詳細へ整理。処理中は実際のスピナーのみ表示。
- **履歴**：写真カード、日時、推定g/kcal、実測登録・手動本数修正の表示、検索、ページ送り、詳細編集・削除、従来の表と誤差集計。
- **料理・栄養**：乾麺履歴選択→食材追加→取り分け→保存。1食材ずつ入力するカード形式と従来の表入力を選択可能。登録レシピと保存料理を別メニューで閲覧。
- **設定**：表示テーマ、撮影ガイド、製品登録・校正、AI学習管理。管理機能の分離は認証ではありません。

## 実装と技術選択

|観点|Streamlit継続（採用）|React＋Python API|
|---|---|---|
|UIの自由度|ネイティブ入力とCSSで4画面・カード・下部ナビを実現。OSカメラの完全制御は制約あり|自由な画面遷移・カメラ制御が可能|
|スマホ操作|カメラ／アップロード、確認→結果、食材カードを実装|細かなトランジション等に向く|
|既存機能|Python処理・SQLite・検品コンポーネントを継続利用|API、画像転送、状態同期の移植が必要|
|コスト・保守|画面モジュール分割と共通トークン。Streamlit更新時にDOMスタイル再検証が必要|クライアント／API双方の依存・テスト・運用が必要|
|起動|既存のPythonコマンド／Windowsバッチを継続|ビルド済み配信か追加起動構成が必要|
|セキュリティ|既存のローカル運用。管理分離のみでは認証にならない|API認証・CORS・アップロード検証等の設計が必要|

今回は移行コストをかけずに主要フローを改善できるためStreamlitを維持。単なる色変更ではなく、`app.py`を画面ルーターに縮小し、home/capture/history/settings/ingredientのモジュールを追加しました。

`ui/design.css` に色・角丸・影・間隔・文字サイズを集約。ライト／ダーク／OS追従、縮小モーション、キーボードフォーカス、44px以上の主要タップ領域、safe-area、画面幅別レイアウトを管理します。テーマ選択はブラウザ接続セッション内に保持されます。モバイルでは動的ビューポートと入力欄のスクロール余白を使い、キーボード表示時もナビゲーションを維持します。

## データの互換性

SQLiteの既存測定に `archived` 列（既定0）を追加。既存行を保持します。実測値の変更前の行を `measurement_edits` に記録し、元の推定g・推定栄養値は書き換えません。削除は一覧からのアーカイブで、元画像・監査用データは残ります。保存済み料理に紐づく測定は変更・削除を拒否し、料理の計算条件との対応を保護します。

料理計算は従来どおり実測重量を優先。食材の不明な栄養値を0で補完しません。学習・QC・モデル選択・製品校正は継続利用できます。

## 起動

リポジトリ直下で：

```sh
python -m streamlit run pasta_weight_app_v2/app.py
```

Windowsでは従来の `pasta_weight_app_v2/start_windows.bat` も使用可能な構成です。ルート起動では `.streamlit/config.toml` が適用されます。Python 3.12の既存環境・依存を使用し、フロントエンドのビルドは不要です。Windows実機での起動は今回未検証です。

スマートフォンからの接続構成は従来と同じです。ブラウザ内カメラにはHTTPSまたはlocalhostの安全なコンテキストが必要で、使用できなければ標準カメラで撮ってアップロードします。公開認証は追加していません。
