# 08 Codex向けロードマップ・タスク一覧

## Sprint 0 — 現状の引継ぎと健全性（写真なしで実施）
- [ ] `README_FIRST.md` と元コードを読む。
- [ ] `requirements.txt` をインストールし、pytestを実行。
- [ ] Streamlit画面起動（可能な環境で）。
- [ ] 既存UIの非推奨警告・例外ハンドリングを修正。
- [ ] `.gitignore`、開発用依存・CI/テストコマンドを整備。
- [ ] 変更点と未検証項目を明文化。

## Sprint 1 — データを入れられる仕組み（写真なしで実施）
- [ ] `dataset_template.csv` に対するバリデータとテスト。
- [ ] 製品・画像・重量・状態のメタデータと保存方式を設計。
- [ ] バッチ単位train/val/test分割のCLIを実装（データリーク防止）。
- [ ] OpenCV推定器の精度レポートをCSVから生成するCLIを実装。
- [ ] UI・推定器・DB・栄養計算の責務を整理。

## Sprint 2 — 画像解析の高度化（サンプルで設計、実写で評価）
- [ ] 広げ：色判定の頑健化、交差／接触を検出して再撮影を促す。
- [ ] 束：断面検出の誤検出・見落としを可視化する。
- [ ] 手動本数入力との誤差の比較機能を追加。
- [ ] 推定不能判定の設計と撮影ガイド。
- [ ] 実写真が来たら処理方式を比較し、必要なら学習器導入。

## Sprint 3 — 学習・評価（実写真が揃ったら）
- [ ] 本数検出・分類・回帰のどれが適切か、ベースラインと比較。
- [ ] 学習データにラベルを付けるワークフロー作成。
- [ ] 学習・検証・テストを再現可能にする。
- [ ] モード別／製品別／重量帯別に誤差を可視化。
- [ ] 実測誤差の報告・失敗例の分析。

## Sprint 4 — スマホ公開（データ保護を確保してから）
- [ ] モバイルUIの操作性確認。
- [ ] ログイン認証・データのアクセス制御。
- [ ] HTTPSでカメラ入力／アップロードを実機テスト。
- [ ] Cloudflare 400 Bad Requestの原因を切り分け。
- [ ] 公開形態と永続DBの運用を選択。

## Sprint 5 — 完成料理への拡張（後回し）
- [ ] レシピ材料・調味料マスタ。
- [ ] **前に測定した乾麺gを選択して料理に紐付ける**。別の日・別人の料理を誤って紐付けない。
- [ ] 料理画像による「カルボナーラ／ボロネーゼ／ミートソース等」の**料理種類の分類**（重量は必須ラベルとしない）。使う画像の使用許諾・出典・クラス偏りを管理。
- [ ] 分類された料理を候補として表示し、利用者が料理名・使った材料・量・人数を確認修正。
- [ ] **料理kcal = 乾麺のgから計算したkcal + 各材料・調味料kcal**。料理1人前は人数・取り分け割合で按分。
- [ ] 写真から隠れた油・チーズ等の量や全材料を自動で確定しない。条件不明時は「標準レシピに基づく概算」と明示。

## 直近の実装で作る成果物（チェックリスト）
- CLI: `validate_dataset`, `split_dataset`, `evaluate_baseline` 相当。
- 検証用・デモ用データと実写真を厳密に区別。
- 自動テストの増加と実行ログ。
- 新しいデータが揃ったら必要なコマンドを一つずつ実行できるREADME。
- `Bad Request` は再現手順・診断ログ・解決が確認できた事実だけを報告。
