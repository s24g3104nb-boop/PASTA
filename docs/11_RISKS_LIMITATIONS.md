# 11 重要な制約・品質上のリスク

## 物理・情報的な限界
- 真上1枚の画像には、重なった麺の内側、本数、断面の深さ、質量に関する情報が欠ける。
- マーカーなしの場合、画像上のピクセルだけからcmや体積へ変換できない。撮影距離・カメラを固定するか、既知の製品仕様を利用する方法が必要。
- 本数方式なら製品・太さ・長さ・割れ・製造差が重量に影響。
- 束の断面方式では奥の麺・先端が揃わない麺を見落とす可能性。
- 独立領域を数える方式では交差があると低く出がち。

## AIについて
- 実写の教師データがない現状で学習済みと称してはならない。
- CGサンプルでのテスト成功は、現実環境での精度の証拠ではない。
- 教師データに秤量誤差や製品差があるとAIの予測にも影響する。
- 予測モデルが不確実な場合は「推定不能」「再撮影」が必要。

## 栄養値について
- 乾麺単体の重量×製品ラベルの栄養値で計算可能。
- 茹で後の水分増減、油・ソース・具材は当面対象外。調理料理のカロリーを乾麺計算のまま表示してはいけない。
- 今のデモ製品の数字は**仮の例示**。食事管理に利用する場合は製品パッケージの実値が必要。

## 情報管理と運用
- 公開Webサービスで写真・履歴が認証なしに閲覧できる設計は避ける。
- Cloudflare Quick Tunnelは検証目的であり、URLが不定・稼働保証なし。メール認証を含む運用設定を検証する。
- 外部公開時は保存データとユーザー識別が適切に分離されている必要がある。
- 研究・提出用の結果は再現手順・データ分割・バージョン・誤差を明示する。
